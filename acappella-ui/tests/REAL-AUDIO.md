# 真实录音测试

合成音频的问题不是不准，是太顺利：频率正好、节奏正好、没有颤音、没有辅音、没有伴奏、采样率永远是 44.1 kHz。这些条件恰好绕开了算法最容易出错的地方。这套测试改用网上能拿到的真实录音，共 21 分钟音频，全部是公版或 CC 授权。

## 语料

| 来源 | 内容 | 授权 |
|---|---|---|
| Choral Singing Dataset (Zenodo 2649950) | 3 首 SATB 合唱，16 位歌手每人一条近讲音轨，附逐帧 f0 标注和逐音标注 | CC BY 4.0 |
| Wikimedia Commons | 7 段录音：两个合唱团、格鲁吉亚复调、艺术歌曲、1920 年代 blues、格里高利圣咏、爵士四重奏伴奏 | PD / CC0 / CC BY / CC BY-SA |

合唱数据集是这套测试的锚点：它有独立于我们算法的 f0 和音符标注，可以算准确率，而不是只看波形好不好看。其余录音没有标注，用来做鲁棒性观察。

音频不放进仓库，体积 1 GB 左右。抓取和预处理脚本在 `acappella-ui/tests/corpus/`，默认写到 `SONNET_TESTDATA` 指向的目录。

## 怎么跑

```bash
cd acappella-ui
node tests/real-audio.mjs scan <manifest.json>        # 无标注录音的统计
node tests/real-eval.mjs <csd-manifest.json> [曲目]    # 有标注的准确率
node tests/rate-check.mjs <44k.wav> <48k.wav> <96k.wav>  # 采样率一致性
node tests/yin-range.mjs                              # 音域下限随采样率变化
```

`tests/analysis.mjs` 复刻引擎每帧的处理：30 fps、4096 点频谱、多基频、谐波门槛、220 ms 漏检保持。用的是工程自己的 `pitch.js`、`multipitch.js`、`fft.js`、`follower.js`、`coldstart.js`，不是另写一套算法。

## 结果

### 单声部音高（YIN，对照数据集 f0 标注）

| 曲目 | 女高 | 女低 | 男高 | 男低 | 八度错 | 50 音分内 |
|---|---|---|---|---|---|---|
| Locus Iste | 96.8% | 97.2% | 96.8% | 95.6% | 0.1–0.8% | 中位 4–9 音分 |
| El Rossinyol | 94.8% | 93.7% | 95.8% | 95.3% | 0–1.5% | 中位 6–7 音分 |
| Niño Dios | 91.2% | 90.6% | 80.1% | 87.8% | 0.1–0.7% | 中位 9–12 音分 |

单声部这一层是可靠的。最快的曲子（Niño Dios，音符中位 0.4 秒）男高掉到 80.1%，错音 15.8%，这是真实演唱里辅音和连音造成的，合成音频不会出现。

### 多基频（16 人混音，逐帧对照四个声部）

| 曲目 | 召回 | 精确 | F1 | 女高召回 | 男低召回 |
|---|---|---|---|---|---|
| Locus Iste | 50.5% | 69.0% | 58.4 | 31.8% | 76.1% |
| El Rossinyol | 35.9% | 62.3% | 45.6 | 13.9% | 57.1% |
| Niño Dios | 46.2% | 74.8% | 57.2 | 23.6% | 68.7% |

按 `pickForPart` 的 2.5 半音容差统计。真实合唱里女高最难检，男低最好检。另有 15% 到 46% 的声部帧只能靠八度认领，也就是检出的音高差了一个八度。README 里写的 F1 约 0.7 在真实 16 人合唱上达不到，实测 0.46 到 0.58。

### 跟谱（单声部，拍误差）

拍误差指光标所在音符的时间区间与真实时刻的距离，0 表示光标正压在这个音上。

| 曲目 | 女高 | 女低 | 男高 | 男低 |
|---|---|---|---|---|
| Locus Iste | 0.01 拍 / 99.6% | 57.6 拍 / 16.5% | 30.4 拍 / 42.7% | 105.8 拍 / 6.2% |
| El Rossinyol | 0.03 / 99.7% | 0.06 / 98.4% | 13.3 / 47.3% | 0.03 / 99.1% |
| Niño Dios | 0.03 / 99.9% | 0.10 / 96.4% | 0.48 / 81.9% | 19.4 / 15.1% |

12 个声部里 7 个能在 1 拍内跟住，5 个会掉队，最严重的落后 105 拍（约 53 秒）。

逐帧追踪掉队过程，原因不是音高检错，是**长休止后的重新进入**：谱面休止时，停留代价只有 0.05，累积代价在静音里越攒越占优；歌唱者重新进来后，即使下一个音的代价接近 0，也要好几秒才能抵掉这份优势。这段时间里 `hold` 不断被路径切换清零，前进判据迟迟不触发。合成测试里休止很短、起音很干净，这个问题不会出现。

这是真实曲目才会暴露的缺陷，修它要动 `follower.js` 的代价结构，风险不小，本次只记录不动手。

### 冷启动定位（3 秒窗口，对照真实拍号）

| 曲目 | 10 秒 | 30 秒 | 50 秒 |
|---|---|---|---|
| Locus Iste | −14.1 拍 | +1.8 | −0.7 |
| El Rossinyol | +0.9 | +0.4 | 拒绝 |
| Niño Dios | 拒绝 | −0.1 | +0.1 |

9 次里 6 次误差在 2 拍内，2 次拒绝定位，1 次锁到 14 拍之前。锁错那次的最优与次优只差 0.02，谱面里正好有两段相似的经过，而定位器攒满 3 秒就接受结果。这说明低区分度阈值（0.6）还不够严，重复乐段仍然会赌错。

### 哼唱转录（真实演唱，不是哼鸣）

| 曲目 | 音符 F1 |
|---|---|
| Locus Iste | 30.3 / 34.9 / 49.8 / 41.6 |
| El Rossinyol | 11.6 / 4.3 / 3.2 / 45.9 |
| Niño Dios | 50.7 / 28.2 / 29.0 / 51.5 |

合计 32%，最低 3.2%。合成测试里报的 0 音分误差只在干净单音上成立。这里用的是带歌词的演唱，比哼鸣难，但差距仍然说明转录离实用还有距离，尤其是 El Rossinyol 这种快而连贯的曲子。

### 无标注录音的鲁棒性

| 录音 | 判为有声的帧 | 每帧声部数 | 八度跳变 | 最高音级占比 |
|---|---|---|---|---|
| 爵士四重奏伴奏（纯器乐） | 95.3% | 1.85 | 1.1% | 18.9% |
| 格鲁吉亚复调 1957 | 98.8% | 2.41 | 7.3% | 12.4% |
| 1920 年代 blues | 99.9% | 2.01 | 11.2% | 24.3% |
| 艺术歌曲（人声加伴奏） | 90.0% | 1.44 | 10.6% | 21.5% |

纯器乐有 95.3% 的帧被判成有人在唱，还转出 275 个假音符。谐波结构门槛只能区分「有谐波列」和「频谱是平的」，分不出人声和乐器。伴奏一响，应用会以为有人在唱，这是物理层面的限制，不是参数没调好，但应该在界面上说清楚。

## 改了什么

采样率相关的两处窗口是真实 bug，已修：

1. `pitch.js` 新增 `yinWindowSize()`。YIN 的可测下限由窗口一半的采样点数决定，固定 2048 点在 96 kHz 时下限升到 93.8 Hz，男低音的 C2 直接测不到；176.4 kHz 时 172 Hz 以下全丢。窗口按时长取，44.1 kHz 和 48 kHz 仍是 2048 点，行为不变。
2. `multipitch.js` 新增 `fftSizeFor()`。固定 4096 点 FFT 在 96 kHz 时频率分辨率减半，谐波求和变粗。现在按 93 ms 取窗，96 kHz 用 8192 点。

改完后同一段真实录音在 44.1、48、96 kHz 下的逐帧音高有 80.4% 一致到 50 音分以内（改之前 34.6%），和 48 kHz 与 44.1 kHz 之间的一致率（80.6%）持平。剩下的差异来自帧对齐，分析帧的采样点位置不同。

调用点：`engine.js`、`hum.js`、`takes.js`，三处都改为按采样率分配缓冲。

## 测试本身的局限

- 合唱数据集的音轨是分声部、分场次录的，靠录像和伴奏对齐，秒级对齐但采样级不保证。
- 跟谱测试用的谱面由逐音标注生成，不是印刷谱。标注里的短空隙会被当成休止，这会影响跟谱结果，上表的掉队有一部分由此放大；换印刷谱或 MIDI 会更接近实际使用。
- 转录测试用的是带歌词的演唱，比哼鸣难，数字偏悲观。
- 无标注录音只能看统计特征，不能算准确率。
